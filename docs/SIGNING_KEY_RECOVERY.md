# 时本正式签名与安全恢复

## 已完成与尚未完成

本次为独立应用 `cn.goff.shiben` 创建了专用 RSA3072 正式签名密钥，保存为加密 PKCS12 文件。目录/秘密文件仅本地可读；未加入 Git，未上传仓库或随源码、APK 分发。项目只保留可公开的证书。

**独立持久备份尚未完成。** 当前工作区仍可能丢失，不能把本地文件存在当作安全异地备份。若这个新私钥再次丢失，将无法给当前安装生成同签名更新。公开证书、旧 APK、源码和 Git 历史都无法恢复私钥。

## 建议由用户亲自完成的离线备份

1. 通过由用户控制的安全文件传输/下载方式获取加密签名文件（PKCS12），存入加密离线盘或受控加密保险库。不要将私钥或密码发到聊天、Issue、GitHub、源码 ZIP，或交给未授权服务。
2. 将密钥密码单独保存在自己的密码管理器中；不要与密钥文件放在同一个明文压缩包。不要在聊天中发送密码。
3. 在自己的受控设备上，用 `keytool -list -keystore <备份的文件> -alias shiben-release` 验证密码有效。让工具在本地交互式询问密码，不将密码直接写进命令行或日志。
4. 对照证书 SHA256：`2bdb75da4e44bff3b8d38cce39807d67e11b6868c965fac23d22812cf7492045`。再保留第二份独立加密备份。

上述步骤是建议路径，并不表示文件已经传出或用户已经完成备份。私钥传输需由用户亲自操作或通过受支持的安全交接进行；本次没有自动上传任何签名秘密。

## 后续维护

- 安装身份始终保持 `cn.goff.shiben`，发布时递增 versionCode。
- 用同一私钥签名；`scripts/sign-release.sh` 可从本地密码文件或本地环境变量读取密码。
- `tests/release/check.py` 会核对本版身份、文案、签名及公开证书。后续改版本时同步更新版本断言，但不要轻易替换既有证书。
- 更换签名者不能直接覆盖现有安装。不要将卸载并清除数据作为默认更新方案。
