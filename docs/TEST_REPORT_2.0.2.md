## 结算等级规则与边界

等级使用任务优先级加权完成度原值，不使用界面四舍五入后的数字。注意力时长不参与等级计算。

| 已知加权完成度原值p | 自动等级 |
| --- | --- |
| 0 ≤ p < 60 | E |
| 60 ≤ p < 70 | D |
| 70 ≤ p < 80 | C |
| 80 ≤ p < 84 | B- |
| 84 ≤ p < 87 | B |
| 87 ≤ p < 90 | B+ |
| 90 ≤ p < 94 | A- |
| 94 ≤ p < 97 | A |
| 97 ≤ p < 100，尚未真正全部完成 | A+ |
| 真正全部完成 | S，可手动选择S、SS、SSS、SSS+ |
| 历史快照、有效进度或优先级信息不足，或总值非有限数 | 未知 |

- 真正100%的条件为：当日任务快照完整、总值有限、至少一个未归档任务；每一个未归档任务的已知进度都恰为100%，优先级有效，权重有限且在0至1之间。归档记录继续保留，但不进入活动任务分母；空日为E，不可选S系列。
- 对60、70、80、84、87、90、94、97各门槛，测试精确边界及 `Math.nextDown` 的边界下方值。99.9999仍为A+；即使浮点加权结果碰巧等于100，只要有任务未完成也仍为A+。
- 80项任务中末项99%的极小权重用例，原始double求和已舍入为100，仍不能获得S。总完成度显示也不会向上越过等级边界：93.999显示93.99%，96.999显示96.99%；上述浮点100但未全部完成的情况显示 `<100%`。
- 真实原生界面验证94%显示A、97%显示A+且无调整入口；真正100%默认S并出现调整入口。
- 选择按日期独立保存，关闭重开SQLite后仍在；改名不清除有效选择。进度降低或新增未完成任务立即清除当日手动等级，再次全部完成回到S，不恢复旧SSS+；不影响其它日期。
- 取消等级选择不保存；Activity重建保留未提交选择；选择默认S清除提高后的覆盖值。非法等级、未完成日期和未来日期不可写入手动等级。
- 计时、补记、删除注意力记录只改变实际时长，不改变手动任务进度及结算等级。

证据：`SettlementGradeTest`、`LedgerSnapshotGradeTest`、`V2ReportsTest`，以及 `api35-final/attention.log`。
