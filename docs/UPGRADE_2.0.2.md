# 时本 2.0.2 升级说明

- 安装身份仍为 `cn.goff.shiben`，versionCode 为 5。正式包必须沿用 V2 的同一签名证书。
- 数据库从 schema 2 升级到 3，只为每日快照添加可为空的 `settlement_grade` 列，不清空、不重建旧表，不改写旧任务、专注片段、删除墓碑或暂停计时的序列化格式。schema 1 可依次升级。
- 新增补记入口位于「今日 → 更多 → 补记注意力时长」。已完成的连续时间按原始时区分配到各日；暂停中的计时也须先结束。已有时段重叠、未来结束、无效时间会明确拒绝，补记不更新任务进度。
- 历史补记沿用该日期留存的任务名。未留存的旧优先级或进度仍显示未知，不使用当前配置补造历史。
- 今日注意力包含手动补记、已保存计时和正在计时的实际投入；暂停排除。导出在一次计时快照上完成，不把临时快照当成新专注记录保存。
- 结算等级只按任务加权完成度原值计算。达到真正的全部完成后默认 S，可选择 S、SS、SSS、SSS+；进度降下去会清除当日手动等级，重新完成后回到 S。选择按日期独立保存。
- 每日 Markdown 改成批准的五类信息：日期与时本标题、注意力总时长、总完成度、任务及各完成度、结算等级。内部和已授权外部每日 Markdown 都会更新为这个精简格式。
- 技术数据仍完整保存在原 SQLite 账本中。Markdown 是可读导出，不是可直接恢复的数据库备份；卸载或清除数据会丢失内部账本。
- PNG 使用原今日绿叶背景的预先模糊版本与近白底板，完整长列表仍分页，多页或多日使用 ZIP。

## 验收要求

正式签名后用原 2.0.1/code4 至 2.0.2/code5 覆盖升级验证。旧表旧列逐值比较（包括记录字节）、设置逐项比较，暂停计时按逻辑字段比较；Markdown 内容因批准的格式调整做语义保留检查，不要求旧文件哈希不变。执行结果单独记录于测试报告，本文不替代验证。
